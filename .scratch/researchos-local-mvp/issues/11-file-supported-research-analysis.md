# 11 — File a supported research analysis

**What to build:** An explicit Research action that preserves a valuable, corpus-supported result as durable wiki knowledge through the same constrained and atomic writer used by ingest.

**Blocked by:** 07 — Compound knowledge across two papers; 10 — Extend chat with live web research.

**Status:** ready-for-agent

- [ ] An ordinary chat answer remains conversational until the researcher explicitly chooses to file it.
- [ ] Filing creates a separate writer job rather than granting write access to the research-chat process.
- [ ] A filed cross-paper synthesis identifies at least two supporting ingested source identities and includes valid physical-page evidence citations.
- [ ] External claims are rejected or omitted unless their supporting PDFs have first become ingested sources.
- [ ] The filed analysis becomes a standalone wiki page with valid frontmatter, explicit wikilinks, and a protected researcher-annotation section.
- [ ] Filing updates the index and appends an activity entry describing the analysis and affected pages.
- [ ] The complete filed analysis publishes as exactly one Git commit after the standard validation gate.
- [ ] Unsupported claims, a single-source cross-paper analysis, modified annotations, or malformed writer output publish nothing.
- [ ] The filed page appears in Wiki, backlinks, search, and Graph only after successful publication.
- [ ] Public-boundary tests cover successful filing, external-evidence exclusion, validation rejection, and ordinary-chat non-persistence.
